Secure Cleaning - Next.js security patch review
Date: 2026-10-04
Status: prepared locally; not committed, merged, pushed or deployed.
Baseline: 2cc6bfe6b42943a3edc359b798d5534494a8668d

Versions and compatibility
Next.js 14.2.35 -> 15.5.27 (Maintenance LTS).
eslint-config-next 14.2.3 -> 15.5.27.
React / React DOM 18.3.1 -> 19.2.8; React type packages moved to 19.2.
PostCSS pinned to 8.5.28, including nested Next.js copies via an npm override.
Removed react-day-picker 8.10.1: no imports anywhere in this repository; its React <=18 peer constraint conflicts with React 19. Existing booking calendar is custom and remains intact.
The lockfile captures associated transitive dependency changes.

Implementation
Migrated dynamic route/page params and searchParams to awaited promises using the official Next.js codemod, then reviewed the changes.
Cleaner portal now awaits cookies. Existing shared auth helpers already await cookies.
Moved serverComponentsExternalPackages to serverExternalPackages and removed the unsupported swcMinify setting.
Preserved security response headers, redirects, authorization, capability checks, email reply-to normalization and base64 calendar attachment handling.
Next.js 15 changes fetch/GET caching defaults. Supabase already uses no-store fetch; protected responses retain private/no-store headers. No new caching opt-ins were added.
No migrations, public API payload changes, or database/data-contract changes. Framework-internal handler parameter types changed.

Manual / runtime verification
Ran the built production app on 127.0.0.1:3115 with synthetic service credentials.
Chrome: booking page rendered; NSW selection enabled address controls; choosing 20 October updated the calendar selection. Admin page rendered the individual staff login form.
Local HTTP: unauthenticated admin quote workflow and regional cleaner APIs returned 401; invalid quote and scope links returned 404 with private/no-store; cleaner portal/jobs/admin rendered without application error.
Browser logs included extension listener warnings/errors; no React hydration error was observed. This is not a claim of a completely clean browser console.
No booking or email was submitted in this upgrade verification. Successful authenticated live sessions, real email delivery and external calendar refresh were not rerun against the upgraded version because it is not deployed. Earlier production checks were on the previous version.

Advisory assessment
Official release: https://nextjs.org/blog/september-2026-security-release
Upgrade guide: https://nextjs.org/docs/app/guides/upgrading/version-15
The September maintainer release recommends 15.5.27 / 16.3.8. The smaller supported major upgrade was selected.
The release also says fixes for one critical and one high vulnerability were postponed due to upstream delays. Applicability is not established from the published note; absence from npm audit is not proof these risks are resolved.
Audit counts are vulnerable package entries, not unique CVEs:
Before: {'info': 0, 'low': 1, 'moderate': 7, 'high': 20, 'critical': 1, 'total': 29}
After: {'info': 0, 'low': 1, 'moderate': 7, 'high': 12, 'critical': 0, 'total': 20}
All 23 direct Next.js advisories reported against 14.2.35 are absent after upgrade. Next.js and PostCSS have no final npm audit finding.
Remaining findings were not force-fixed: unrelated major upgrades/downgrades (Tailwind, Google APIs, ExcelJS) would expand this patch and need separate compatibility review. Some remaining findings may allow compatible dependency updates; they remain explicitly open.
